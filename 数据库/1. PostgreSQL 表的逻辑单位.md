PostgreSQL 分区表笔记

# 1. PostgreSQL 表的逻辑单位

PostgreSQL 的逻辑对象层级：

```
Cluster（数据库集群）
    |
    ├── Database（数据库）
    |       |
    |       └── Schema（模式）
    |               |
    |               ├── Table（表）
    |               ├── View（视图）
    |               ├── Index（索引）
    |               └── Function（函数）
```

例如：

```
test_db.gis.road
```

表示：

```
Database = test_db
Schema   = gis
Table    = road
```

其中：

- Database：类似 MySQL 的 database
- Schema：PostgreSQL 特有的逻辑命名空间
- Table：实际业务表

------

# 2. PostgreSQL 三种表类型

## 2.1 常规表（Regular Table）

普通业务表。

创建：

```sql
CREATE TABLE user_info(
    id bigint,
    name varchar(50)
);
```

结构：

```
Database
 |
 Schema
   |
   user_info
       |
       数据
```

特点：

- 数据存储在 PostgreSQL 自己管理的存储空间
- PostgreSQL 负责：
  - 数据存储
  - 索引
  - 事务
  - MVCC
  - 增删改查

适用于：

- 用户表
- 订单表
- 业务数据表

------

## 2.2 外部表（Foreign Table）

外部表本身不保存数据。

它只是 PostgreSQL 访问外部数据源的一个入口。

结构：

```
PostgreSQL

Foreign Table
        |
        |
        ↓

外部数据源
(MySQL / CSV / 其他 PostgreSQL)
```

例如：

```sql
CREATE FOREIGN TABLE remote_user(
    id int,
    name text
)
SERVER mysql_server;
```

查询：

```sql
SELECT *
FROM remote_user;
```

实际上查询的是外部数据。

用途：

- 跨数据库访问
- 查询 CSV 文件
- 数据同步
- 数据联邦

理解：

```
普通表：
表就是数据


外部表：
表只是一个数据访问入口
```

------

## 2.3 分区表（Partitioned Table）

分区表：

> 一个逻辑大表，实际拆成多个物理子表。

例如：

普通表：

```
orders

2025数据
2026数据
2027数据

全部混在一起
```

分区表：

```
orders
 |
 ├── orders_2025
 |
 ├── orders_2026
 |
 └── orders_2027
```

查询：

```sql
SELECT *
FROM orders
WHERE create_time >= '2026-01-01';
```

数据库可以只访问：

```
orders_2026
```

这叫：

```
分区裁剪（Partition Pruning）
```

------

# 3. 分区逻辑是谁定义？

答案：

> 分区规则由开发者设计，数据库负责自动路由数据。

数据库不会自动决定：

- 按时间分
- 按地区分
- 按 ID 分

这些需要开发者决定。

------

# 4. 创建分区表

示例：

```sql
CREATE TABLE orders(
    id bigint,
    create_time timestamp,
    amount decimal
)
PARTITION BY RANGE(create_time);
```

这一句只定义：

```
分区方式：
RANGE

分区字段：
create_time
```

也就是：

```
我要按照 create_time 做范围分区
```

但是：

还没有定义具体范围。

------

# 5. 定义具体分区

继续创建子表：

```sql
CREATE TABLE orders_2026
PARTITION OF orders
FOR VALUES FROM ('2026-01-01')
             TO ('2027-01-01');
```

表示：

```
orders_2026

保存：

2026-01-01 <= create_time < 2027-01-01
```

再创建：

```sql
CREATE TABLE orders_2027
PARTITION OF orders
FOR VALUES FROM ('2027-01-01')
             TO ('2028-01-01');
```

最终：

```
orders
 |
 ├── orders_2026
 |       时间:
 |       2026年
 |
 └── orders_2027
         时间:
         2027年
```

------

# 6. 分区类型

PostgreSQL 常用三种：

------

## 6.1 RANGE 分区（范围分区）

适合：

- 时间
- 数字范围

例如：

```sql
PARTITION BY RANGE(create_time);
```

数据：

```
2026-01
2026-02
2026-03
```

或者：

```
id 1-10000
id 10001-20000
```

------

## 6.2 LIST 分区（列表分区）

适合：

固定枚举值。

例如：

省份：

```sql
CREATE TABLE user_info(
    id bigint,
    province varchar(20)
)
PARTITION BY LIST(province);
```

创建：

```sql
CREATE TABLE user_guangdong
PARTITION OF user_info
FOR VALUES IN ('广东');
```

效果：

```
user_info

 |
 ├── user_guangdong
 |       province='广东'
 |
 └── user_beijing
         province='北京'
```

------

## 6.3 HASH 分区（哈希分区）

适合：

数据均匀分散。

例如：

```sql
PARTITION BY HASH(id);
```

数据库根据：

```
hash(id)
```

自动分配。

适合：

- 大量数据平均拆分
- 不关心业务范围

------

# 7. 字符串能不能分区？

可以。

但是选择方式很重要。

------

## 字符串 + LIST（推荐）

例如：

地区：

```
广东
北京
上海
```

使用：

```sql
PARTITION BY LIST(province);
```

------

## 字符串 + RANGE（少用）

例如：

```sql
PARTITION BY RANGE(name);
```

按照字符串排序：

```
A < B < C ...
```

例如：

```sql
FROM ('A') TO ('N')
```

表示：

```
A <= name < N
```

问题：

- 字符排序规则影响结果
- 大小写影响
- 不适合随机字符串

------

# 8. 分区字段如何选择？

选择原则：

## 1. 经常查询过滤的字段

例如：

经常：

```sql
WHERE create_time BETWEEN ...
```

选择：

```
create_time
```

------

## 2. 数据增长规律

例如：

日志：

每天新增：

```
100万
```

适合：

```
按天/月/年分区
```

------

## 3. 数据生命周期管理

例如：

日志：

```
最近3个月：
在线查询


3个月以前：
删除/归档
```

分区：

```
drop partition
```

比：

```
delete 大量数据
```

效率高。

------

# 9. 分区的价值

分区不是简单拆表。

主要作用：

## 1. 减少扫描范围

没有分区：

```
10亿数据
全部扫描
```

有分区：

```
只扫描目标分区
```

------

## 2. 提高维护效率

删除旧数据：

普通表：

```sql
DELETE FROM logs
WHERE create_time<'2025-01-01';
```

可能删除大量数据。

分区：

```sql
DROP TABLE logs_2024;
```

瞬间删除。

------

## 3. 提升管理能力

例如：

```
订单表

2024分区
2025分区
2026分区
```

可以单独：

- 备份
- 迁移
- 删除
- 压缩

------

# 10. 总结

| 类型   | 数据位置       | 特点                 | 使用场景   |
| ------ | -------------- | -------------------- | ---------- |
| 常规表 | PostgreSQL内部 | 普通表               | 业务数据   |
| 外部表 | 外部系统       | 访问外部数据         | 跨库、文件 |
| 分区表 | 多个内部子表   | 逻辑一张表，物理拆分 | 大数据表   |

分区核心：

```
开发者定义分区规则
        |
        ↓
数据库根据规则自动路由数据
```

创建：

```sql
PARTITION BY RANGE(create_time)
```

只是：

```
选择分区策略
```

真正的范围：

```sql
FOR VALUES FROM (...) TO (...)
```

才是：

```
具体分区规则
```

选择原则：

```
时间字段 → RANGE

枚举字段 → LIST

均匀拆分 → HASH
```
