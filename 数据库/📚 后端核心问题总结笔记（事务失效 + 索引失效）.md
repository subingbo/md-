# 📚 后端核心问题总结笔记（事务失效 + 索引失效）

------

# 🧩 第一部分：Spring 事务失效

------

## 🧠 一、核心本质

> Spring 事务基于 **AOP 代理机制**

👉 必须满足两个条件：

```text
1. 通过代理对象调用
2. 满足事务回滚规则
```

否则：

```text
@Transactional = 无效
```

------

## ⚙️ 二、事务执行流程（理解失效根因）

```text
Controller
   ↓
Proxy（事务代理）
   ↓
目标方法
   ↓
提交 / 回滚事务
```

👉 如果没有经过 Proxy → 事务不会生效

------

## 🚨 三、常见事务失效原因

------

### 1️⃣ 方法内部调用（自调用）

```java
@Service
public class UserService {

    public void A() {
        B();  // ❌ 不走代理
    }

    @Transactional
    public void B() {}
}
```

❌ 原因：

- 内部调用没有经过代理

✅ 解决：

```java
((UserService) AopContext.currentProxy()).B();
```

或拆分 Bean

------

### 2️⃣ 方法不是 public

```java
@Transactional
protected void save() {} // ❌
```

👉 原因：

- Spring 默认只拦截 public 方法

------

### 3️⃣ 异常类型不对

```java
@Transactional
public void test() throws Exception {
    throw new Exception(); // ❌ 不回滚
}
```

👉 默认只回滚：

- RuntimeException ✅
- Exception ❌

✅ 解决：

```java
@Transactional(rollbackFor = Exception.class)
```

------

### 4️⃣ 捕获异常导致不回滚

```java
try {
    // DB操作
} catch (Exception e) {
    // ❌ 吞异常
}
```

👉 事务依赖异常抛出

✅ 正确：

```java
throw new RuntimeException(e);
```

------

### 5️⃣ Bean 没被 Spring 管理

```java
UserService userService = new UserService(); // ❌
```

✅ 正确：

```java
@Autowired
private UserService userService;
```

------

### 6️⃣ 事务传播机制问题

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
```

👉 行为：

- 挂起当前事务
- 新开事务

❗ 结果：

- 外层回滚 ❌
- 内层已提交 ✅

------

### 7️⃣ 数据库不支持事务

```sql
ENGINE=MyISAM  -- ❌
ENGINE=InnoDB  -- ✅
```

------

### 8️⃣ readOnly = true

```java
@Transactional(readOnly = true)
```

👉 可能导致：

- 不 flush
- 更新不生效

------

### 9️⃣ private / final / static 方法

```java
@Transactional
private void test() {} // ❌
```

------

### 🔟 多事务管理器配置错误

```java
@Transactional(transactionManager = "xxx")
```

👉 配错 → 不生效

------

## 🔍 四、事务问题排查流程

```text
1. 是否内部调用（最常见）
2. 方法是否 public
3. 是否捕获异常
4. 异常类型是否正确
5. 是否 Spring Bean
6. 数据库是否支持事务
7. 传播机制是否合理
```

------

## 🎯 五、事务一句话总结

> **事务生效 = 代理调用 + 异常触发回滚机制**

# 🧩 第二部分：MySQL 索引失效

------

## 🧠 一、核心本质

> 索引失效 = 优化器认为不用索引更快

```text
能用索引 ≠ 一定用索引
```

------

## ⚙️ 二、索引基础

- InnoDB 索引结构：**B+Tree**
- 特点：
  - 有序
  - 最左匹配
  - 不支持跳跃

------

## 🚨 三、常见索引失效原因

------

### 1️⃣ 对索引列做函数

```sql
WHERE YEAR(create_time) = 2024
```

❌ 索引失效

✅ 正确：

```sql
WHERE create_time >= '2024-01-01'
```

------

### 2️⃣ 隐式类型转换

```sql
WHERE phone = 13800138000
```

👉 实际：

```sql
CAST(phone AS INT)
```

❌ 失效

------

### 3️⃣ 最左前缀原则

```sql
INDEX(name, age)
WHERE age = 20  -- ❌
```

------

### 4️⃣ 范围查询截断索引

```sql
WHERE name='张三' AND age>20 AND city='北京'
```

👉 city 失效

------

### 5️⃣ != / <> / NOT IN

```sql
WHERE status != 1
```

❌ 通常不走索引

------

### 6️⃣ OR 使用不当

```sql
WHERE name='张三' OR age=20
```

❌ 索引可能失效

------

### 7️⃣ LIKE '%xxx'

```sql
WHERE name LIKE '%张'
```

❌ 不走索引

------

### 8️⃣ 区分度低

```sql
WHERE gender='男'
```

❌ 优化器放弃索引

------

### 9️⃣ IS NOT NULL

```sql
WHERE col IS NOT NULL
```

❌ 可能失效

------

### 🔟 查询数据量太大

```sql
SELECT * FROM user WHERE name='张三'
```

👉 回表成本高 → 全表扫描

------

### 1️⃣1️⃣ 统计信息不准

```sql
ANALYZE TABLE user;
```

------

### 1️⃣2️⃣ 索引设计不合理

- 顺序错误
- 区分度低
- 冗余索引

------

## 🔍 四、索引排查方法

------

### 1️⃣ EXPLAIN

```sql
EXPLAIN SELECT ...
```

关键字段：

| 字段 | 含义             |
| ---- | ---------------- |
| type | ALL = 全表扫描 ❌ |
| key  | 使用索引         |
| rows | 扫描行数         |

------

### 2️⃣ SQL 检查清单

```text
函数 / 计算
隐式转换
最左前缀
范围查询
like '%'
or
!=
```

------

### 3️⃣ 索引设计检查

- 是否匹配查询条件
- 是否高区分度
- 是否需要联合索引

------

## 📊 五、优化建议

------

### ✅ SQL 编写

- 不对索引列运算
- 避免类型转换
- 多用 =
- 遵守最左匹配

------

### ✅ 索引设计

- 高频查询字段
- 高区分度优先
- 联合索引合理设计

------

### ✅ 查询优化

- 覆盖索引
- limit 限制
- 避免 select *

------

## 🎯 六、索引一句话总结

> **索引失效 = 破坏 B+Tree 有序性 或 优化器认为成本更高**

------

------

# 🧠 总体对比总结（高频面试点）

| 维度     | 事务失效          | 索引失效        |
| -------- | ----------------- | --------------- |
| 本质     | 没走代理          | 优化器不选索引  |
| 核心机制 | AOP               | B+Tree          |
| 常见原因 | 自调用 / 异常处理 | 函数 / 最左前缀 |
| 排查工具 | 日志 / 调试       | EXPLAIN         |

------

# 🎯 最终总口诀（面试直接背）

```text
事务要走代理，异常必须抛
自调用最常见，public不能少

索引最怕乱计算，类型转换直接废
最左匹配要遵守，范围之后全失效
like左模必失效，or乱用也崩溃
区分度低不用它，优化器说不划算
```
