# Reactor 模型与 Redis 网络事件处理

## 1. 基本问题

服务器需要处理大量客户端连接：

例如 Redis：

```
客户端A
客户端B
客户端C
...
客户端N
```

每个客户端都会产生：

- 建立连接
- 发送数据
- 接收响应

传统方式：

```
一个连接
    |
    v
一个线程处理
```

如果有：

```
10000个客户端
```

就可能需要：

```
10000个线程
```

问题：

- 线程创建成本高
- 上下文切换频繁
- CPU资源浪费

因此出现了：

> IO多路复用 + Reactor模型

------

# 2. IO多路复用

## 2.1 什么是IO多路复用

核心思想：

> 一个线程同时监听多个网络连接，由操作系统告诉线程哪些连接有事件。

传统：

```
线程1 -> fd1
线程2 -> fd2
线程3 -> fd3
```

IO多路复用：

```
              一个线程

                 |
                 |

        +--------+--------+
        |        |        |

       fd1      fd2      fd3
```

线程不用一直轮询：

```
fd1有没有数据？

fd2有没有数据？

fd3有没有数据？
```

而是：

```
操作系统：

哪个fd有事件，我通知你。
```

------

# 3. epoll是什么

epoll是Linux提供的IO多路复用机制。

注意：

> epoll不是负责执行任务，而是负责通知事件。

错误理解：

```
epoll:

发现数据

↓

调用Handler处理
```

正确：

```
Linux内核:

发现fd有事件

↓

通知应用程序

↓

应用程序自己处理
```

------

# 4. epoll工作流程

## 4.1 注册fd

Redis启动：

创建监听socket：

```
fd=5
```

注册到epoll：

```
epoll监听:

fd=5

事件:
EPOLLIN
```

意思：

告诉内核：

> 如果这个fd有事件，通知我。

------

## 4.2 epoll_wait等待事件

Redis进入事件循环：

```
while(true){

    events = epoll_wait();

    处理事件;

}
```

执行：

```
epoll_wait()
```

之后：

Redis线程阻塞。

状态：

```
Redis线程

      |
      |
      v

 epoll_wait()

      |
      |
    睡眠
```

------

# 5. fd的两种类型

Reactor里面最重要的概念：

> 监听连接的fd和通信数据的fd不是同一个。

------

## 5.1 监听fd

例如：

```
fd=5
```

作用：

```
等待新的客户端连接
```

它负责：

```
accept()
```

不负责：

```
读取GET命令
```

------

## 5.2 客户端fd

客户端连接后：

```
accept(fd=5)
```

产生：

```
fd=8
```

作用：

```
和某一个客户端通信
```

负责：

```
read()

write()
```

------

关系：

```
              Redis


          fd=5

     监听socket

          |
          |
       accept()

          |
          v


     fd=8

   客户端A通信


     fd=9

   客户端B通信
```

------

# 6. 为什么需要新的fd？

问题：

> 为什么不直接用监听fd处理数据？

因为监听socket和通信socket职责不同。

监听fd：

```
负责:

有没有新的客户端
```

通信fd：

```
负责:

客户端发送的数据
```

类似电话：

```
客服电话号码:

10086

负责接入电话


接通以后:

客服人员

负责和具体用户交流
```

TCP也是：

```
监听socket:

等待连接


连接socket:

通信
```

------

# 7. TCP连接建立过程

## 7.1 客户端连接

客户端：

```
connect()
```

Linux内核完成：

```
TCP三次握手
```

完成后：

连接进入监听socket队列。

例如：

```
监听队列:

conn1
conn2
conn3
```

------

## 7.2 Redis发现新连接

Redis：

```
epoll_wait()
```

返回：

```
fd=5
```

表示：

```
监听socket有新连接
```

Redis执行：

```
accept(fd=5)
```

得到：

```
fd=8
```

------

# 8. 数据读取流程

客户端发送：

```
GET name
```

流程：

```
客户端

   |
   v

Linux TCP协议栈

   |
   v

socket缓冲区

   |
   v

fd=8可读

   |
   v

epoll就绪队列
```

内核发现：

```
fd=8

EPOLLIN
```

唤醒Redis线程。

------

# 9. Redis什么时候执行epoll_wait？

Redis启动后：

进入事件循环：

```
while(true){

    events = epoll_wait();

    for(event : events){

        处理事件;

    }

}
```

所以：

Redis大部分时间：

```
阻塞在epoll_wait()
```

没有请求：

```
epoll_wait()
一直等待
```

有请求：

```
内核唤醒

epoll_wait返回
```

------

# 10. epoll_wait返回几个fd？

不是一次一个。

可以一次返回多个。

例如：

同时：

```
客户端A发送数据

fd=8


客户端B发送数据

fd=9


客户端C发送数据

fd=10
```

epoll就绪队列：

```
fd=8
fd=9
fd=10
```

epoll_wait：

返回：

```
[
 fd=8,
 fd=9,
 fd=10
]
```

Redis：

循环处理：

```
fd=8

read()

处理


fd=9

read()

处理


fd=10

read()

处理
```

------

# 11. epoll_wait不是读取整个队列

准确说：

> epoll_wait从就绪事件中获取事件，最多返回指定数量。

例如：

```
epoll_wait(epfd, events, 1024, -1)
```

最多返回：

```
1024个事件
```

如果有：

```
10000个fd
```

需要多次处理。

------

# 12. Reactor模型

整体结构：

```
                  Redis线程


                      |
                      |

                epoll_wait()


                      |

        +-------------+-------------+

        |                           |


     fd=5事件                    fd=8事件


 新连接事件                  数据读取事件


        |                           |


    accept()                   Handler


        |                           |


    新fd=8                  read/write
```

------

# 13. Redis为什么以前可以单线程？

Redis：

```
网络IO

+
命令执行

+
事件循环

都是一个线程
```

但是Redis命令：

例如：

```
GET

SET

INCR
```

主要操作：

```
内存数据结构
```

速度非常快。

所以：

```
单线程
+
epoll
+
内存操作
```

可以达到很高性能。

------

# 14. 单线程的问题

如果业务执行很慢：

例如：

```
执行Lua脚本

10秒
```

线程：

```
收到请求

↓

执行Lua

↓

10秒不能处理其他请求
```

导致：

```
其他客户端全部等待
```

------

# 15. Redis 6多线程优化

Redis 6：

不是命令执行多线程。

而是：

网络IO多线程。

以前：

```
一个线程:

epoll

accept

read

执行命令

write
```

现在：

```
IO线程:

read/write网络数据


        |

        v


主线程:

执行Redis命令
```

------

# 核心总结

## fd关系

```
监听fd:

负责发现新连接

accept()


客户端fd:

负责数据读写

read/write()
```

------

## epoll关系

```
Linux内核:

监听fd状态


        |

        v


epoll就绪队列


        |

        v


epoll_wait返回事件


        |

        v


Redis线程处理
```

------

## 最重要三句话

1. **TCP连接建立由Linux内核完成，Redis通过accept获取已经建立的连接。**
2. **epoll只负责通知哪个fd有事件，不负责执行任务。**
3. **Reactor模型就是：一个线程通过epoll监听大量fd，然后根据事件类型调用accept或者Handler处理。**
