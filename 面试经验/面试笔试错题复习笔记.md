下面逐题说明。

### 1. 排序算法的稳定性

如果两个元素的关键字相等，排序后它们的相对先后顺序仍然不变，这个排序算法就是稳定的。

- 常见稳定排序：冒泡排序、插入排序、归并排序。
- 常见不稳定排序：选择排序、快速排序、堆排序。

稳定性在只看数值时不明显，但对“先按一个字段排序，再按另一个字段排序”的对象数据很重要。

**练习：** 对学生记录先按姓名排序，再使用一种稳定算法按成绩排序。成绩相同的学生是否仍保持姓名顺序？

**答案：** 是。第二次排序稳定，因此相同成绩记录的原相对顺序不会改变。

### 2. 大顶堆删除堆顶

原始大顶堆：

```text
[10, 8, 9, 3, 7, 5]
```

删除堆顶不能只删掉 10。标准步骤是：

1. 用最后一个元素 5 覆盖根节点，临时得到 `[5, 8, 9, 3, 7]`。
2. 比较根节点和两个孩子，选择较大的孩子 9 交换。
3. 得到合法大顶堆 `[9, 8, 5, 3, 7]`。

关键口诀：**末尾补根，向下调整，每次和较大的孩子交换。**

**练习：** 从大顶堆 `[12, 9, 10, 4, 7, 6]` 中删除堆顶，调整后的数组是什么？

**答案：** 先用 6 补根，得到 `[6, 9, 10, 4, 7]`；6 与较大的孩子 10 交换，最终为 `[10, 9, 6, 4, 7]`。

### 3. Redis AOF 刷盘策略

AOF 先记录写命令，再根据配置决定何时请求把数据同步到持久化存储。

| 策略 | 含义 | 性能与风险 |
| --- | --- | --- |
| `always` | 每次写操作后都刷盘 | 数据更安全，但写入开销最大 |
| `everysec` | 通常每秒刷盘一次 | 性能与可靠性的常用平衡方案，故障时可能丢失约 1 秒数据 |
| `no` | 交给操作系统决定刷盘时机 | 性能较好，但丢失窗口更不可控 |

还要区分 `write` 与 `fsync`：`write` 通常只是把内容交给操作系统缓冲区，`fsync` 才是请求系统把缓冲内容同步到持久化设备。

**练习：** 业务希望性能较好，同时最多只接受约 1 秒的数据丢失风险，应优先选择哪种策略？

**答案：** `everysec`。

### 4. 哈夫曼树与 WPL

权值为 `2、3、7、9`。构造哈夫曼树时，每轮都选择当前最小的两个权值合并：

```text
2 + 3 = 5
5 + 7 = 12
9 + 12 = 21
```

WPL（带权路径长度）可以直接用每次合并得到的新权值之和计算：

```text
WPL = 5 + 12 + 21 = 38
```

也可以按叶子深度验算：9 的深度为 1，7 的深度为 2，2 和 3 的深度为 3，因此：

```text
WPL = 9×1 + 7×2 + 2×3 + 3×3 = 38
```

容易出错的地方是：每次合并后，要把新权值重新放回当前权值集合，再继续选最小的两个。

**练习：** 权值为 `1、2、4、5`，写出合并序列并计算 WPL。

**答案：** `1+2=3`，`3+4=7`，`5+7=12`；`WPL=3+7+12=22`。

### 5. Java 重载：`show(null)` 调用哪个方法

假设存在以下两个重载：

```java
static void show(Object value) {
    System.out.println("Object");
}

static void show(String value) {
    System.out.println("String");
}

show(null);
```

`null` 可以赋给任意引用类型，所以两个方法都适用。Java 会在可用重载中选择参数类型更具体的方法。`String` 是 `Object` 的子类，因此调用 `show(String)`，输出：

```text
String
```

注意：如果重载参数是两个互不相关的类型，例如 `show(String)` 和 `show(Integer)`，那么 `show(null)` 无法判断谁更具体，会产生编译错误。

**练习：** 同时存在 `test(CharSequence)` 和 `test(String)`，执行 `test(null)` 会调用哪个方法？

**答案：** 调用 `test(String)`，因为 `String` 实现了 `CharSequence`，是更具体的类型。

### 6. JavaScript：`var`、循环与 `setTimeout`

典型代码如下：

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

输出为：

```text
3
3
3
```

原因有两个：

1. `var` 没有块级作用域，三个回调共享同一个 `i`。
2. `setTimeout` 的回调要等当前同步代码执行完后才有机会运行；循环结束时，`i` 已经变成 3。

如果改成 `let i`，每轮循环会得到独立的块级绑定，因此输出 `0、1、2`。

**练习：** 下面代码输出什么？

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

**答案：** 依次输出 `0、1、2`。

## 二、需要复习，但不能直接算作新增错题的内容

以下内容来自回答不完整、曾表示不清楚，或题干记录不完整的知识点。它们应该进入复习计划，但不能据此声称又答错了某一道完整题。

### 1. Java 基础

#### Integer 缓存

自动装箱通常调用 `Integer.valueOf`。常见实现会缓存 `-128～127`，因此缓存范围内的两个装箱对象可能是同一对象；范围外通常不是同一对象。比较数值应使用 `equals` 或拆箱后比较，不应依赖 `==` 比较对象身份。

**练习：** 以下结果分别是什么？

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);
System.out.println(c == d);
System.out.println(c.equals(d));
```

**答案：** 常见情况下依次为 `true、false、true`。面试核心是区分对象身份比较与数值比较。

#### 方法重载

除前面的 `null` 题外，还要掌握：重载在编译期根据参数的静态类型选择；基本类型转换、装箱和可变参数之间存在匹配优先级；返回值不同不能单独构成重载。

**练习：** `void f(long x)` 与 `void f(Integer x)` 同时存在，调用 `f(1)` 选择哪个？

**答案：** 选择 `f(long)`。基本类型的拓宽转换优先于装箱。

### 2. 代码阅读

代码阅读不要只背结论，建议固定按四步分析：

1. 先区分编译期问题与运行期问题。
2. 标出变量的作用域和生命周期。
3. 写出同步代码的执行顺序。
4. 最后处理异步回调、动态分派和异常路径。

**练习：** 看到一段含重载、继承和异步回调的代码时，应该先猜输出还是先判断能否编译？

**答案：** 先判断能否编译；不能通过编译的代码没有运行期输出。

### 3. 数据结构

复习重点是哈夫曼树、堆的向上/向下调整，以及排序稳定性。做题时不要只记算法名单，还要能用一组带重复关键字的数据解释“稳定”的含义，并能手算一次堆调整和哈夫曼合并。

**练习：** 往大顶堆插入新元素时通常向哪个方向调整？删除堆顶时呢？

**答案：** 插入末尾后通常向上调整；用末尾元素替换堆顶后通常向下调整。

### 4. Redis

#### Hash 渐进式 rehash

需要掌握的概念是：扩容或收缩时准备新哈希表，不一次性搬完所有数据，而是在后续操作中逐步迁移；迁移期间读写逻辑需要同时考虑新旧表，迁移完成后释放旧表。这样可以避免一次性搬迁大量数据造成长时间阻塞。

**练习：** 渐进式 rehash 期间，为什么查询不能只查旧表？

**答案：** 因为部分键可能已经迁移到新表；只查旧表会把已迁移的键误判为不存在。

#### AOF

除三种刷盘策略外，还要能说清 AOF 记录的是什么、为什么需要重写，以及 `write` 与 `fsync` 的区别。

**练习：** AOF 重写的主要目的是什么？

**答案：** 用能够恢复当前数据状态的更精简命令集合替代冗长历史，减小 AOF 文件并降低恢复成本。

### 5. Spring

#### AOP 的 JDK 动态代理与 CGLIB

- JDK 动态代理基于接口，核心是 `Proxy` 与 `InvocationHandler`。
- CGLIB 通常通过生成目标类的子类来代理，因此受 `final` 类和 `final` 方法限制。
- 同一个对象内部通过 `this` 调用另一个增强方法时，调用往往没有经过代理对象，AOP 可能不生效。

**练习：** 一个没有实现接口的普通类需要被 Spring AOP 代理，通常采用哪种方式？为什么 `final` 方法难以被这种方式增强？

**答案：** 通常采用 CGLIB；它依赖生成子类并重写方法，而 `final` 方法不能被重写。

### 6. 动态规划

#### 背包 DP 与一维压缩

0/1 背包中，每件物品最多使用一次。二维状态可写成“前 `i` 件物品、容量为 `j` 时的最大价值”；压缩成一维后，为避免当前物品在同一轮被重复使用，容量必须从大到小遍历。

完全背包允许同一物品重复使用，所以压缩成一维后通常让容量从小到大遍历，使当前轮更新后的状态可以继续参与计算。

**练习：** 0/1 背包中有两件物品：重量和价值分别为 `(2,3)`、`(3,4)`，容量为 5，最大价值是多少？一维 DP 的容量应按什么方向遍历？

**答案：** 两件都选，最大价值为 7；容量从大到小遍历。

## 四、建议复习顺序

1. 先重做六道已确认错题，做到能解释原因，而不是只记选项。
2. 集中训练代码阅读：每题都写出“能否编译、同步顺序、变量作用域、最终输出”。
3. 手算哈夫曼树和堆调整，再复习排序稳定性。
4. 对比 Redis 的 AOF 三种策略，并口述一次渐进式 rehash。
5. 最后用短代码巩固 Spring AOP 与背包 DP。

复习达标标准：同一知识点换一种问法后，仍能独立给出结论、过程和原因。
