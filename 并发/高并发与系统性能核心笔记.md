# 一、为什么高并发系统讨厌锁

锁的本质：

```text
同一时间只能一个线程操作共享资源
```

例如：

```java
synchronized(lock) {
    count++;
}
```

问题：

- 线程等待
- context switch
- cache miss
- cache line bouncing
- CPU调度风暴
- 死锁
- 串行化

------

## 锁最大的本质问题

锁会让：

```text
并发 -> 串行
```

例如：

```text
100线程抢1把锁
```

结果：

```text
99线程等待
1线程工作
```

------

# 二、什么是 Context Switch（上下文切换）

CPU 同一时间只能执行有限线程。

例如：

```text
16核CPU
同时最多真正执行16线程
```

如果：

```text
100线程
```

OS 必须不停切换。

------

## Context Switch 过程

线程A -> 线程B：

### 保存A现场

- 寄存器
- PC
- 栈
- CPU状态

### 恢复B现场

然后继续执行B。

------

## Context Switch 为什么昂贵

因为会导致：

- CPU cache失效
- TLB失效
- 调度开销
- 内存访问增加

------

# 三、线程为什么会导致性能下降

如果：

```text
线程数 > CPU核心数
```

就会：

```text
频繁context switch
```

CPU大量时间：

```text
不是处理业务
而是在切线程
```

------

## 理想情况

```text
线程数 ≈ CPU核心数
```

且：

```text
线程操作独立数据
```

此时性能接近线性扩展。

------

# 四、CAS 是什么

CAS：

```text
Compare-And-Swap
```

一种无锁原子操作。

流程：

```text
比较内存值
如果没变则更新
否则失败重试
```

Java：

```java
AtomicInteger
```

底层大量使用 CAS。

------

## CAS 优点

- 无阻塞
- 少context switch
- 高性能

------

## CAS 缺点

高竞争下：

```text
大量自旋重试
```

CPU会飙高。

------

# 五、Zero-Copy 是什么

Zero-Copy：

```text
减少CPU参与的数据复制
```

目标：

```text
减少：
用户态 <-> 内核态 copy
```

------

## 传统IO

```text
磁盘
 ↓ DMA
内核缓冲区
 ↓ CPU memcpy
用户缓冲区
 ↓ CPU memcpy
Socket缓冲区
 ↓ DMA
网卡
```

CPU会大量 memcpy。

------

## Zero-Copy

例如：

```c
sendfile()
```

流程：

```text
磁盘
 ↓ DMA
内核缓冲区
 ↓ DMA / 页引用
网卡
```

用户态不参与。

------

## Zero-Copy 优点

- 减少CPU copy
- 减少context switch
- 提高吞吐

------

# 六、DMA 是什么

DMA：

```text
Direct Memory Access
```

硬件直接搬运数据。

例如：

```text
磁盘 -> 内存
内存 -> 网卡
```

不需要CPU逐字节copy。

------

# 七、epoll 是什么

epoll：

```text
Linux高性能IO多路复用机制
```

作用：

```text
一个线程管理大量连接
```

------

## select 问题

select：

```text
每次遍历所有fd
O(n)
```

即使：

```text
10万个连接
只有1个活跃
```

也要全遍历。

------

## epoll 核心思想

```text
只返回活跃连接
```

内核维护：

```text
ready list
```

socket活跃时：

```text
主动通知
```

------

## epoll 提升的是什么

不是：

```text
单次IO更快
```

而是：

```text
高并发连接管理效率
```

------

# 八、Event Loop 是什么

本质：

```text
while(true){
    epoll_wait()
    处理事件
}
```

------

## Event Loop 优点

- 少线程
- 少context switch
- 少锁
- 高吞吐

------

# 九、Redis 为什么单线程还这么快

Redis 快的原因：

------

## 1. 纯内存

内存：

```text
纳秒级
```

磁盘：

```text
毫秒级
```

------

## 2. 单线程避免锁

没有：

- 锁竞争
- context switch
- cache bouncing

------

## 3. epoll + Event Loop

一个线程：

```text
处理大量连接
```

------

## 4. IO多路复用

大量连接：

```text
实际上都在等待
```

------

# 十、为什么通信有时候比锁更好

通信当然也有成本。

例如：

- channel
- 消息队列
- Actor mailbox

------

## 但锁的问题是：

竞争会恶化。

例如：

```text
100线程抢1锁
```

可能导致：

- 阻塞
- 唤醒
- cache同步
- context switch风暴

------

## 通信的核心优势

不是：

```text
零成本
```

而是：

```text
减少共享写
```

# 十一、如何让线程操作不同数据

核心思想：

```text
数据所有权（Ownership）
```

即：

```text
这份数据归哪个线程负责
```

------

## 最常见方法：Hash分片

```text
uid % 4
```

例如：

```text
Thread1 -> uid % 4 == 0
Thread2 -> uid % 4 == 1
```

# 十五、Saga 与最终一致性

现代互联网更喜欢：

```text
最终一致性
```

而不是：

```text
强一致
```

------

## Saga 思想

大事务拆成小事务。

失败时：

```text
补偿操作
```

例如：

```text
A扣100失败
-> A加100回去
```

------

## MQ方案

A扣款成功：

```text
发送消息
```

B消费消息：

```text
执行加钱
```

失败：

```text
重试
```

# 最终核心总结

现代高性能系统的本质：

```text
不要让CPU等待
```

CPU最擅长：

```text
独立连续计算
```

CPU最讨厌：

```text
共享
同步
锁竞争
context switch
cache失效
```

因此：

现代系统设计核心：

```text
减少共享
减少同步
减少线程切换
让数据尽量本地化
```
