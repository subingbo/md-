# 锁作为“内存中的通行证”补充笔记

------

# 一、锁本质上是什么

锁本质可以理解成：

```text
内存中的“通行证/占用标记”
```

例如：

```java
volatile int lock = 0;
```

这里：

```text
lock
```

本质就是：

```text
共享内存中的一个状态位
```

------

# 二、为什么说锁像“通行证”

因为：

多个线程：

```text
都想进入临界区
```

但：

系统规定：

```text
必须先拿到“进入许可”
```

这个许可：

就是：

```text
锁状态
```

------

# 三、自旋锁本质

例如：

```java
while(!CAS(lock,0,1)) {
}
```

含义：

------

## lock = 0

表示：

```text
没人持有通行证
```

任何线程：

```text
都能尝试抢
```

------

## CAS成功

例如：

```text
CAS(lock,0,1)
```

成功后：

```text
当前线程拿到通行证
```

------

## lock = 1

表示：

```text
通行证已被占用
```

其他线程：

```text
不能进入临界区
```

只能：

```text
继续自旋等待
```

------

# 四、锁为什么必须放共享内存

因为：

多个线程：

```text
必须看到同一个状态
```

否则：

线程A：

看到：

```text
lock=0
```

线程B：

也看到：

```text
lock=0
```

就会：

```text
同时进入临界区
```

数据直接乱掉。

因此：

锁必须：

```text
存放在所有线程可见的共享内存
```

------

# 五、锁真正保护的是什么

不是线程。

而是：

```text
共享数据的一致性
```

例如：

```java
count++
```

多个线程同时修改：

```text
会发生竞争
```

于是：

锁作为：

```text
内存中的访问许可
```

保证：

```text
同一时刻只有一个线程能修改
```

------

# 六、为什么CAS能实现锁

因为：

CAS保证：

```text
“检查+修改”
```

是：

```text
CPU原子操作
```

例如：

```text
如果lock还是0
就改成1
```

过程中：

```text
不会被其他线程打断
```

因此：

```text
只有一个线程能成功抢到通行证
```

------

# 七、锁和owner thread的关系

锁本身：

```text
是共享内存状态
```

但：

锁内部通常还会记录：

```text
owner = 当前线程
```

例如：

```text
owner = Thread-A
```

含义：

```text
当前通行证归Thread-A使用
```

------

# 八、为什么锁可以理解成“门”

可以这样类比：

------

## 临界区

像：

```text
机房
```

------

## 锁

像：

```text
门禁卡
```

------

## lock=0

表示：

```text
门禁卡空闲
```

------

## lock=1

表示：

```text
有人正在使用门禁卡
```

------

## CAS成功

表示：

```text
抢到门禁卡
```

于是：

```text
允许进入机房
```

------

# 九、为什么释放锁本质是改内存

例如：

```java
lock = 0;
```

本质：

```text
把通行证放回共享内存
```

于是：

其他线程：

```text
下一次CAS
就可能成功
```

------

# 十、现代锁其实远比这个复杂

例如：

```java
ReentrantLock
```

内部：

除了lock state：

还有：

- owner thread
- wait queue
- park/unpark
- 重入计数
- AQS队列

但核心仍然是：

```text
共享内存中的状态控制
```

------

# 十一、synchronized也是一样

例如：

```java
synchronized(lock){}
```

对象头里的monitor：

本质也是：

```text
共享状态 + owner thread
```

------

# 十二、最终一句话

锁本质上可以理解成：

```text
共享内存中的“通行证/占用标记”
```

线程通过：

```text
CAS或mutex机制
```

竞争这个通行证，

拿到后：

```text
才允许进入临界区操作共享数据。
```
