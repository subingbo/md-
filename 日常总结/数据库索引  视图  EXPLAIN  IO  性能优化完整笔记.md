# 数据库核心知识完整笔记（索引 / 视图 / EXPLAIN / IO / 优化）

# 一、数据库三层模式结构

## 1. 外模式（External Schema）
- 用户/应用看到的数据视图
- 不同用户可不同视图
- 本质：局部逻辑结构

👉 不存数据，只是“展示方式”

---

## 2. 模式（Schema / 概念模式）
- 全数据库统一逻辑结构
- 表、字段、关系、约束
- DBA设计层

👉 不包含数据，只描述结构

---

## 3. 内模式（Internal Schema）
- 数据物理存储方式
- B+树索引、数据页、文件组织
- 存储引擎层

---

## ⭐ 总结

| 层级   | 本质     |
| ------ | -------- |
| 外模式 | 用户视图 |
| 模式   | 逻辑结构 |
| 内模式 | 存储结构 |

---

# 二、数据独立性

## 1. 逻辑数据独立性
- 外模式 ↔ 模式映像
- 改表结构 → 不影响应用（理想情况）

---

## 2. 物理数据独立性
- 模式 ↔ 内模式映像
- 改存储方式 → 不影响SQL

---

## ⚠️ 本质
> 数据独立性 = 通过映射减少影响，而不是完全不影响

---

# 三、视图（View）

## 1. 本质
> 视图 = 保存的 SQL 查询（不是数据）

---

## 2. 特点
- ❌ 不存数据
- ✔ 动态执行 SQL
- ✔ 用于封装查询逻辑
- ✔ 用于权限控制

---

## 3. 示例

```sql
CREATE VIEW v_user AS
SELECT id, name FROM user WHERE age > 18;
```

------

## 4. 支持操作

✔ SELECT
✔ JOIN
✔ WHERE
✔ GROUP BY
✔ 聚合函数

------

## 5. 本质

> 视图 = SQL逻辑封装层

------

# 四、GROUP BY 在视图中的作用

## 本质

> 定义固定聚合规则

------

## 示例

```sql
CREATE VIEW v_user_sum AS
SELECT user_id, SUM(amount)
FROM orders
GROUP BY user_id;
```

------

## 作用

- 封装统计逻辑
- 查询时自动执行聚合

------

## ⚠️ 注意

- 不存结果
- 每次查询重新计算

------

# 五、普通视图 vs 物化视图 vs 表

| 类型     | 是否存数据 | 是否实时 | 性能 |
| -------- | ---------- | -------- | ---- |
| 表       | ✔          | ✔        | 中   |
| 视图     | ❌          | ✔        | 慢   |
| 物化视图 | ✔          | ❌        | 快   |

------

## 1. 物化视图

```sql
CREATE MATERIALIZED VIEW mv_user AS ...
```

- 存结果
- 需 refresh
- 查询极快

------

## 2. 本质区别

- View = 现算
- Materialized View = 预计算

------

# 六、索引（Index）

## 1. 本质

> 用空间换时间（B+Tree）

------

## 2. 联合索引

```sql
(a, b, c)
```

------

## 最左前缀原则

必须从 a 开始连续使用

------

## ❌ 失效情况

- 跳过左列
- 函数操作
- LIKE '%xxx'
- 隐式类型转换
- OR跨列
- 范围查询截断后续索引

------

## AND vs OR

### AND

- 逐步收敛
- 通常使用索引

### OR

- 多路径查询
- 可能 index merge 或全表扫描

------

# 七、EXPLAIN（执行计划）

## 1. 本质

> 查看 SQL 的执行方式

------

## 2. 核心字段

### type（最重要）

| type   | 含义         |
| ------ | ------------ |
| const  | 主键         |
| eq_ref | 唯一索引JOIN |
| ref    | 普通索引     |
| range  | 范围查询     |
| index  | 扫索引       |
| ALL    | 全表扫描     |

------

### key

- 使用索引
- NULL = 未用索引

------

### rows

- 预估扫描行数

------

### Extra

- Using index（覆盖索引）
- Using filesort（排序）
- Using temporary（临时表）

------

## 判断索引是否生效

- type ≠ ALL
- key != NULL
- rows 越小越好

------

# 八、为什么走索引可能更慢

## 核心原因：IO

------

## 1. IO类型

| 类型    | 特点     |
| ------- | -------- |
| 顺序 IO | 连续读取 |
| 随机 IO | 跳跃读取 |

------

## 2. 索引慢原因

### ❌ 随机 IO

- 一条记录一次磁盘跳转
- B+Tree + 回表

------

### ✔ 全表扫描

- 顺序读取数据页
- cache命中高
- 预读机制

------

## 3. 慢的典型场景

- 返回数据比例高
- 回表次数多
- 随机 IO 爆炸

------

## 4. 本质

> 索引 = 缩小范围，不等于一定更快

------

# 九、随机 IO 本质

## 定义

> 每次访问数据都跳到磁盘不同位置

------

## 示例

索引访问：

Block9 → Block2 → Block15 → Block3

👉 随机 IO（慢）

------

## 顺序扫描：

Block1 → Block2 → Block3 → Block4

👉 顺序 IO（快）

------

# 十、终极总结

## 1. 视图

> SQL逻辑封装，不存数据

------

## 2. 物化视图

> 预计算结果缓存

------

## 3. 索引

> 优化访问路径，不保证最快

------

## 4. EXPLAIN

> 分析 SQL 执行计划

------

## 5. 性能本质

数据库性能 =

> IO模式 + 扫描范围 + 回表成本 + 计算成本

------

# 🚀 一句话总纲

> 数据库优化的本质不是“是否走索引”，而是“是否减少随机 IO 与无效扫描”
