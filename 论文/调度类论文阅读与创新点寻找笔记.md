# 调度类论文阅读与创新点寻找笔记

## 1. 调度研究的核心思想

调度（Scheduling）的本质：

> 在有限计算资源下，决定任务如何分配、什么时候执行，使系统性能达到目标。

一般形式：

```
任务(Task)
   |
   v
调度算法(Scheduler)
   |
   v
资源(Resource)
```

目标通常不是单一的，而是优化：

- 完成时间（Makespan）
- 延迟（Latency）
- 吞吐量（Throughput）
- 资源利用率（Resource Utilization）
- 能耗（Energy Consumption）
- 成本（Cost）
- 负载均衡（Load Balance）

# 2. 不要研究 ThreadPoolExecutor 本身

## 错误方向

例如：

> 修改 ThreadPoolExecutor 参数，提高性能


例如：

- corePoolSize 调大
- 换 BlockingQueue
- 修改拒绝策略


问题：

JDK 已经提供这些机制。

容易变成：

> 工程配置优化

创新性弱。

---

## 正确方向

研究：

> 如何做调度决策。


例如：

任务来了：

```
Task1
Task2
Task3
```

资源：

```
Node1
Node2
Node3
```

问题：

```
Task1 去哪里？
Task2 去哪里？
Task3 去哪里？
```

# 3. 动态调度的核心

动态调度不是简单改线程数量。

动态调度：

```
任务到达

↓

获取系统状态

↓

调度决策

↓

选择资源

↓

执行

↓

反馈结果

↓

更新策略
```


---

# 4. 动态调度需要哪些信息？

## 4.1 任务信息

例如：

```
任务类型
任务大小
CPU需求
内存需求
优先级
Deadline
```

---

## 4.2 资源状态

例如：

```
CPU利用率

Memory

网络

IO

当前任务数量

队列长度
```

---

## 4.3 历史信息

因为任务执行时间一开始不知道。

所以：

第一次：

```
任务A

执行耗时：

800ms
```

记录：

```
TaskA:
800ms
```


多次之后：

```
TaskA:

800
750
900
```

得到：

平均耗时：

```
816ms
```

用于下一次调度。

# 6. 看论文如何寻找创新点

不要问：

> 我要发明什么算法？


应该问：

> 论文方案在哪些情况下不成立？

---

# 方法1：看论文假设

论文：

```
假设任务执行时间已知
```

问题：

现实：

不知道。


创新：

```
任务执行时间预测
```

---

# 方法2：看输入特征

论文输入：

```
CPU
Memory
```

但是没有：

```
网络延迟

IO

历史负载

服务调用关系
```


创新：

增加新的状态。


---

# 方法3：看实验场景

论文：

```
静态任务
```

现实：

```
任务不断到达
```


创新：

静态调度

↓

动态调度


---

# 方法4：看 Future Work

论文最后：

```
Future work:
考虑更多因素
```

这些通常就是改进方向。

# 方向3：DAG任务调度


任务有依赖：

```
A

↓

B    C

↓

D
```


不能随便执行。


目标：

让整体完成时间最低。


---

## 常见算法

HEFT：

Heterogeneous Earliest Finish Time


---

## 创新

原：

静态DAG


改：

动态DAG：

```
任务运行过程中产生新任务
```

# 9. 一个可实现的本科课题示例

## 题目

```
基于任务特征感知的动态任务调度方法研究
```


---

## 基础方案

传统：

```
Round Robin

Least Load
```


---

## 改进方案

加入：

```
任务历史耗时

当前资源状态

任务优先级
```


设计评分：

```
Score=

0.4*任务耗时

+

0.3*资源负载

+

0.3*等待时间
```


选择：

```
最佳资源
```


---

## 实验

模拟：

```
10个节点

1000个任务
```


比较：

| 方法        | Makespan | 延迟 | 资源利用率 |
| ----------- | -------- | ---- | ---------- |
| Round Robin |          |      |            |
| Least Load  |          |      |            |
| 改进算法    |          |      |            |

# 核心思想

本科论文创新通常不是：

```
创造全新算法
```

而是：

```
已有方法

+

现实不足

+

补充一个因素

+

实验验证提升
```

调度论文寻找创新点：

重点看：

1. 假设
2. 输入特征
3. 实验限制
