# GeoScene Pro 图层异常显示排错报告

## 一、问题背景

在将地理信息数据入库后，使用 GeoScene Pro 加载数据库中的空间图层时，出现了异常渲染问题。

数据来源原本为 SHP 文件，但在实际生产流程中采用了：

```text
SHP → CSV → 数据库(PostGIS)
```

的转换链路。

------

## 二、问题现象

在 GeoScene Pro 中加载数据库空间图层后，出现以下异常：

### 1. 图层无法完整显示

表现为：

- 有时仅显示部分要素
- 有时整个图层完全不显示

### 2. 图层存在“闪烁”现象

具体包括：

- 点击地图时，被选中的区块轮廓会“一闪而过”
- 鼠标滚轮缩放地图时，图层会短暂出现后再次消失
- 图层显示状态不稳定

### 3. 数据实际存在

虽然图层不可见，但：

- 可以进行要素选择
- 属性表可正常读取
- 空间对象并未丢失

说明问题更偏向于：

```text
几何对象渲染异常
```

而非：

```text
数据缺失
```

------

# 三、初步怀疑与排查过程

------

## 阶段1：怀疑原始数据损坏

最开始怀疑：

```text
SHP 原始数据本身存在问题
```

于是进行了验证：

### 验证方法

直接将原始 SHP 文件拖入 GeoScene Pro。

### 验证结果

图层能够：

- 正常显示
- 正常缩放
- 正常渲染

### 结论

说明：

```text
原始 SHP 数据本身没有问题
```

问题出现在：

```text
入库流程之后
```

------

## 阶段2：怀疑 CSV 中转导致数据损坏

由于数据流程较长：

```text
SHP → CSV → DB
```

开始怀疑：

```text
CSV 中转过程中 geometry 数据精度或结构发生损坏
```

于是进一步验证。

------

### 验证方法

将：

```text
数据库导入前的 CSV
```

重新转换回 SHP 文件，再直接加载到 GeoScene Pro。

### 验证结果

重新生成的 SHP：

- 可以正常显示
- 没有闪烁问题

### 结论

说明：

```text
CSV 本身并未导致 geometry 丢失
```

至少：

- 坐标数据仍然有效
- 基本拓扑结构仍然存在

------

## 阶段3：怀疑数据库 geometry 存储异常

进一步怀疑：

```text
数据库中的 geometry 对象可能存在兼容性问题
```

于是采用其他 GIS 软件进行验证。

------

### 使用 QGIS 验证

通过 QGIS 直接连接数据库并渲染空间图层。

### 验证结果

QGIS 中：

- 图层显示正常
- 无闪烁
- 无丢失

### 关键发现

说明：

```text
数据库中的 geometry 并非完全损坏
```

而是：

```text
GeoScene Pro 对 geometry 的容错能力低于 QGIS
```

即：

不同 GIS 引擎对非法几何对象的容忍程度不同。

------

# 四、问题定位

通过与 GeoScene Pro 客服沟通后，得到一个关键方向：

```text
geometry 对象可能存在“容差范围内重复节点”
```

即：

## 几何对象存在隐性拓扑问题

常见表现包括：

- 重复节点
- 极短边
- 自相交
- 环方向异常
- 非法 Polygon
- 精度误差导致的重合点

这些问题：

- 在 QGIS 中可能被自动容错
- 在 GeoScene Pro 中则可能导致渲染引擎异常

因此才会出现：

```text
图层能被选中
但无法稳定渲染
```

的现象。

------

# 五、错误修复过程

------

## 尝试1：GIS 软件自带修复工具

分别尝试：

- GeoScene Pro 修复工具
- QGIS Geometry 修复工具

### 结果

修复无明显效果。

------

## 尝试2：脚本级 Geometry 修复

随后采用脚本方式，对 geometry 做进一步清洗：

包括：

- 删除重复节点
- 修复非法 polygon
- 统一精度
- 重建 geometry
- 修复拓扑结构

### 修复结果

修复后重新入库：

- GeoScene Pro 图层恢复正常
- 无闪烁
- 可稳定缩放与渲染
- 所有图层完整显示

问题最终解决。

------

# 六、根本原因分析

问题本质并不是：

```text
数据丢失
```

而是：

```text
geometry 几何对象存在轻微拓扑异常
```

这些异常：

- 不影响普通读取
- 不影响数据库存储
- 不影响 QGIS 渲染

但会影响：

```text
GeoScene Pro 的空间渲染引擎
```

尤其是在：

- 动态缩放
- GPU 渲染
- 空间索引加速
- 面对象边界计算

时容易触发异常。

------

# 七、最终解决方案

## 原流程（存在问题）

```text
SHP
 ↓
CSV 中转
 ↓
数据库入库
```

问题：

- geometry 在多次转换中容易引入精度问题
- CSV 无法天然保证空间拓扑完整性

------

## 新流程（修复后）

```text
SHP
 ↓
脚本修复 geometry
 ↓
直接入库 PostGIS
```

优化点：

- 避免 CSV 中转
- 保留原始 geometry 精度
- 入库前先做拓扑修复

------

# 八、经验总结

## 1. GIS 数据“能读取”不代表“完全合法”

很多 geometry：

- 可以查询
- 可以选择
- 可以显示部分内容

但仍可能：

```text
不满足严格的拓扑规范
```

------

## 2. 不同 GIS 软件容错能力不同

本次案例中：

| 软件         | 表现     |
| ------------ | -------- |
| QGIS         | 正常     |
| GeoScene Pro | 渲染异常 |

说明：

```text
QGIS 对非法 geometry 容忍度更高
```

因此：

```text
QGIS 能显示 ≠ geometry 完全正常
```

------

## 3. CSV 不适合作为空间数据中转格式

CSV：

- 不保存拓扑
- 不保存 SRID
- 不保存 geometry 类型约束
- 精度容易丢失

对于复杂空间数据：

```text
应尽量避免：
SHP → CSV → DB
```

------

## 4. 入库前必须进行 geometry 校验

建议在 PostGIS 入库前统一执行：

```sql
ST_IsValid(geometry)
```

以及：

```sql
ST_MakeValid(geometry)
```

必要时：

- 去重节点
- Simplify
- SnapToGrid
- RemoveRepeatedPoints

------

# 九、建议的标准化流程

推荐后续统一采用：

```text
原始 SHP
   ↓
Geometry 合法性检查
   ↓
脚本修复非法对象
   ↓
直接导入 PostGIS
   ↓
建立空间索引
   ↓
GIS 平台验证显示
```

推荐避免：

```text
SHP → CSV → DB
```

这种会破坏空间结构的流程。

------

# 十、结论

本次问题最终确认为：

```text
geometry 存在隐性拓扑异常
```

并非：

- 数据丢失
- 数据库故障
- GeoScene Pro 软件问题

而是：

```text
GeoScene Pro 对非法 geometry 更敏感
```

通过：

```text
脚本修复 geometry 拓扑结构
```

后问题彻底解决。

最终优化后的流程：

```text
修复 geometry → 直接入库
```

显著提升了：

- 数据稳定性
- GIS 渲染兼容性
- 空间数据可靠性。
