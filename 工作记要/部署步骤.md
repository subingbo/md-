# 业务镜像 ARM 构建、tar 离线交付与推送 Harbor

本文说明：**开发方构建 ARM64 业务镜像 → 导出 tar → 传到甲方电脑 → `docker load` → 推送到甲方 Harbor → K8s 发版** 的完整步骤。

更详细的 build + 公司 Harbor 直推备忘见 [HARBOR-PUSH.md](../HARBOR-PUSH.md)。

---

## 一、适用场景

| 项 | 说明 |
|----|------|
| 开发方 | 从源码编译 jar 并 `docker buildx` 构建 `linux/arm64` 镜像，或直接使用已有 tar |
| 甲方 | 导入/推送机器须为 **ARM64**（`linux/arm64`） |
| 目标 | 镜像进入甲方 Harbor，供 K8s `business.yaml` 拉取 |
| 范围 | **仅 11 个业务微服务**，不含中间件、Kingbase、system-server |

与 [business.yaml](./business.yaml) 保持一致：

| 项 | 值 |

| Harbor 地址 | `harbor.cce.up.gz`（yaml 中可能写 `harbor.cce.up.gz:443`） |
| Harbor 项目 | `gdbhyzt` |
| 镜像路径 | `harbor.cce.up.gz/gdbhyzt/gjy/<服务名>:<版本>` |
| 当前版本（示例） | `1.0.260622`（以 `business.yaml` 中 `image:` 为准） |

## 三、流程总览

```text
【开发方】切换 client-k8s 环境
    → Maven 打包 + build-images-arm64.ps1（linux/arm64）
    → save-business-arm64.ps1 导出 tar
    → 传到甲方 ARM 电脑
【甲方】docker load
    → docker login Harbor
    → docker push（11 个）
    → 核对 business.yaml 版本 → kubectl rollout
```

若已有 tar 或本机已 build 好镜像，可跳过构建，从「导出 tar」或「传输」步骤开始。

## 四、开发方：构建 ARM64 业务镜像

### 4.1 前置条件

| 项 | 要求 |
|----|------|
| 环境 | Windows + **Docker Desktop**（已启动），支持 **buildx** |
| 架构 | 脚本固定 `--platform linux/arm64`；**推荐在 ARM 机器上构建**，x86 交叉构建较慢 |
| 基础镜像 | 需能拉取 `eclipse-temurin:21-jre`（arm64）；离线环境须预先 `docker load` |
| Dockerfile | 统一在 `deploy/DockerFile/`（gateway、infra-server、gzmap-biz） |

### 4.2 切换甲方 K8s 配置（打进 jar）

发版给甲方 K8s 时，先同步 classpath 为 `client-k8s`（`application-k8s.yaml` 等）：

```powershell
cd D:\Amap\special-bond-accessibility-platform-back
.\config\scripts\use-env.ps1 client-k8s
```

### 4.3 构建命令

在仓库根目录执行：

```powershell
cd D:\Amap\special-bond-accessibility-platform-back

# 版本号须与 business.yaml 中 image tag 一致
$env:BUNDLE_VERSION = "1.0.260622"

# 可选：强制无缓存重建（等同 docker build --no-cache）
# $env:DOCKER_NO_CACHE = "1"

# 可选：jar 已打好时跳过 Maven
# $env:SKIP_MAVEN = "1"

powershell -ExecutionPolicy Bypass -File .\deploy\test_deploy\build-images-arm64.ps1
```

### 4.4 脚本做了什么

[build-images-arm64.ps1](../build-images-arm64.ps1) 依次完成：

1. **`mvn -Dmaven.test.skip=true clean package`**（除非 `SKIP_MAVEN=1`）
2. 对每个服务执行 **`docker buildx build --platform linux/arm64 --load`**
3. 镜像直接打 Harbor 全路径 tag：`harbor.cce.up.gz/gdbhyzt/gjy/<服务名>:<BUNDLE_VERSION>`

构建的 11 个服务与 [business.yaml](./business.yaml) 一致：

| 镜像 tag 名 | Maven 模块 |
|-------------|------------|
| gateway | `yudao-gateway` |
| infra | `yudao-module-infra/yudao-module-infra-server` |
| trans / plan / construct / detail / gzmap-infra / community / monitor / analysis / stat | 各 `gzmap-parent/*-service/*-biz`（共用 `gzmap-biz/Dockerfile`） |

**不含** `system-server`（由甲方外部环境提供）。

### 4.5 构建后校验

```powershell
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" | Select-String "gdbhyzt/gjy"
```

应看到 11 个镜像，且 `TAG` 为 `1.0.260622`（或你设置的 `BUNDLE_VERSION`）。

### 4.6 开发方一键命令（build + save）

```powershell
cd D:\Amap\special-bond-accessibility-platform-back
.\config\scripts\use-env.ps1 client-k8s
$env:BUNDLE_VERSION = "1.0.260622"
powershell -ExecutionPolicy Bypass -File .\deploy\test_deploy\build-images-arm64.ps1
powershell -ExecutionPolicy Bypass -File .\deploy\test_deploy\save-business-arm64.ps1
```

## 五、开发方：导出 tar 包

### 方式 A：构建完成后导出（常规发版）

构建成功后继续执行：

```powershell
cd D:\Amap\special-bond-accessibility-platform-back

$env:BUNDLE_VERSION = "1.0.260622"   # 与 build 时一致
powershell -ExecutionPolicy Bypass -File .\deploy\test_deploy\save-business-arm64.ps1
```

[save-business-arm64.ps1](../save-business-arm64.ps1) 将本机 11 个 Harbor tag 镜像 `docker save` 为一个 tar，输出：

- `deploy/test_deploy/images/cspon-gjy-business-images-arm64-<版本>.tar`
- `deploy/test_deploy/images/cspon-gjy-business-images-arm64.tar`（固定名副本）

### 方式 B：直接使用已有 tar

仓库或交付目录中通常已有，无需再 build / save：

```text
deploy/test_deploy/images/cspon-gjy-business-images-arm64.tar
deploy/test_deploy/images/cspon-gjy-business-images-arm64-<版本>.tar
```

确认文件存在且版本与待发 `business.yaml` 一致即可。

### 方式 C：本机已有镜像，仅导出（跳过 build）

若本机 Docker 里已有对应版本的 `harbor.cce.up.gz/gdbhyzt/gjy/*` 镜像，只跑方式 A 中的 `save-business-arm64.ps1` 即可。

## 六、传输到甲方电脑

将 tar 通过 U 盘、内网 SFTP、`scp` 等方式传到甲方可运行 Docker 的 **ARM64** 机器，例如：

```bash
# 在开发机或中转机上执行（路径按实际修改）
scp deploy/test_deploy/images/cspon-gjy-business-images-arm64.tar root@<甲方IP>:/opt/
```

## 七、甲方电脑：导入镜像

登录甲方机器后：

```bash
cd /opt
docker load -i cspon-gjy-business-images-arm64.tar
```

验证（应看到 11 个业务镜像，tag 与 tar 打包时一致）：

```bash
docker images | grep gdbhyzt/gjy
```

**成功标志：** 列出 `gateway`、`infra`、`trans` 等 11 个仓库，且 `TAG` 为预期版本（如 `1.0.260622`）。

**若报 `exec format error`：** 当前机器不是 ARM64，无法使用本 tar 包。

## 八、甲方电脑：登录 Harbor 并推送

### 8.1 登录

```bash
docker login harbor.cce.up.gz -u <账号> -p '<密码>'
```

HTTPS 正常时无需配置 `insecure-registries`。

### 8.2 推送 11 个镜像（Linux / bash）

```bash
VERSION="1.0.260622"    # 改成 tar 内实际 tag
NS="harbor.cce.up.gz/gdbhyzt/gjy"

for svc in gateway infra trans plan construct detail gzmap-infra community monitor analysis stat; do
  echo "==> push $NS/$svc:$VERSION"
  docker push "$NS/$svc:$VERSION"
done
```

### 8.3 甲方使用 Windows + Docker Desktop

load 完成后，在 PowerShell 中手动登录并推送（与 8.2 相同逻辑）：

```powershell
docker login harbor.cce.up.gz -u <账号> -p '<密码>'

$VERSION = "1.0.260622"   # 改成 tar 内实际 tag
$NS = "harbor.cce.up.gz/gdbhyzt/gjy"

@("gateway","infra","trans","plan","construct","detail","gzmap-infra","community","monitor","analysis","stat") | ForEach-Object {
  Write-Host "==> push $NS/${_}:$VERSION"
  docker push "$NS/${_}:$VERSION"
}
```

### 8.4 Harbor 地址与 tar 内 tag 不一致时

若甲方 Harbor 域名或项目名与 tar 内嵌 tag 不同，需 **retag 后再 push**，示例：

```bash
OLD="harbor.cce.up.gz/gdbhyzt/gjy"
NEW="harbor.cce.up.gz/gdbhyzt/gjy"   # 改成甲方实际地址/项目
VERSION="1.0.260622"

docker tag "$OLD/gateway:$VERSION" "$NEW/gateway:$VERSION"
docker push "$NEW/gateway:$VERSION"
# 其余 10 个服务同理
```

推送完成后，在 Harbor 控制台确认 `gdbhyzt/gjy` 项目下 11 个仓库均有对应 tag。

## 九、K8s 发版核对

推送 Harbor 成功后，在 K8s 集群侧：

### 9.1 确认 business.yaml 镜像版本

[business.yaml](./business.yaml) 中 11 处 `image:` 的 tag 须与刚 push 的版本一致，例如：

```text
harbor.cce.up.gz:443/gdbhyzt/gjy/gateway:1.0.260622
```

### 9.2 确认拉镜像凭证

`business.yaml` 使用 `imagePullSecrets: gdbhyzt`。若集群尚未创建，参考 [harbor-secret.yaml](./harbor-secret.yaml)：

```bash
kubectl create secret docker-registry gdbhyzt \
  --docker-server=harbor.cce.up.gz \
  --docker-username=<账号> \
  --docker-password='<密码>' \
  --namespace=default
```

节点上测试拉取：

```bash
docker pull harbor.cce.up.gz/gdbhyzt/gjy/gateway:1.0.260622
# 或 crictl pull ...
```

### 9.3 应用并滚动更新

```bash
kubectl apply -f business.yaml -n default

# 单服务示例
kubectl rollout restart deployment/gjy-gateway-server -n default
kubectl rollout status deployment/gjy-gateway-server -n default

# 全部 11 个业务 Deployment
for d in gjy-gateway-server gjy-infra-server gjy-trans-service gjy-plan-service \
  gjy-construct-service gjy-detail-service gjy-infra-service gjy-community-service \
  gjy-monitor-service gjy-analysis-service gjy-stat-service; do
  kubectl rollout restart deployment/$d -n default
done
```

验收：

```bash
kubectl get pods -n default | grep gjy
curl -s http://<节点IP>:30480/actuator/health
```

完整 K8s 首次部署（中间件、Kingbase、Nacos）见 [K8S-DEPLOY.md](../K8S-DEPLOY.md)。

## 十、常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| build 很慢 / 卡住 | x86 交叉编译 arm64 | 换 ARM 开发机构建，或耐心等待 buildx |
| `Maven package failed` | 编译错误 | 先本地 `mvn -DskipTests package` 排查 |
| `Build failed` / 基础镜像拉不下 | 无外网或缺 temurin arm64 | 离线 `docker load` 导入 `eclipse-temurin:21-jre` |
| `exec format error` | 非 ARM64 机器 load | 换 ARM64 宿主机导入 |
| `Image missing`（save 阶段） | 未 build 或版本不一致 | 先跑 `build-images-arm64.ps1`，或检查 `BUNDLE_VERSION` |
| `401 Unauthorized` | Harbor 账号/密码错误 | `docker logout harbor.cce.up.gz` 后重登 |
| `denied: requested access to the resource is denied` | 无 push 权限或路径错误 | 确认项目 `gdbhyzt`、路径 `gjy/<服务名>` |
| push 报镜像不存在 | tag 版本写错 | `docker images` 查看 load 后的实际 tag |
| Pod `ImagePullBackOff` | 节点拉不到 Harbor | 检查 `gdbhyzt` Secret、网络、Harbor 上 tag 是否存在 |
| yaml 用 `:443` 但 push 不带端口 | 正常 | Docker 将 `harbor.cce.up.gz` 与 `:443` 视为同一 registry |
